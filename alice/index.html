它是怎么工作的？

同一串字节，用两套不同的码表去读，就会读出完全不同的字符。爱丽丝语正是利用了这一点：
方向第一步第二步结果
正常 → 爱丽丝语UTF-8 编码cp932 解码你好 → 菴螂ｽ
爱丽丝语 → 正常cp932 编码UTF-8 解码菴螂ｽ → 你好

为什么会有损？

并非所有 UTF-8 字节序列都能在 cp932 里找到对应字符。找不到的字节会变成 U+FFFD（�），这部分信息在还原时永久丢失。中文因字节分布原因较易触发， 日文与英文则可完美往返。

为什么本页不需要后端？

浏览器原生只有 utf-8 编解码器，而 shift_jis 解码器 的错误处理与算法所依据的 cp932 并不一致（非法字节组合的消耗规则、 0xA0/0xFD-0xFF 的私有区映射都不同）。所以本页内嵌了一份逐项校验过的 cp932 码表 （60 个前导字节 × 188 个尾随字节 = 11280 项），在浏览器里按同样的规则手写解码器 —— 结果是： 本页与该算法最初的 Python 实现逐字节等价（1138 组用例 + 9408 条编码表条目 + 3097 组 UTF-8 编码，零差异）。

两处「浏览器 ≠ Python」的具体差异

这两条是本页必须自带码表的原因，用 你好 一测就露馅：
差异Python cp932浏览器 shift_jis
单字节 A0 / FD / FE / FF 映射到私有区 U+F8F0~F8F3 判为非法 → �
前导字节后跟未定义尾随字节（如 87 E6） 只消耗前导 1 字节，再继续解析 吃掉 2 字节，两字节一起报废

于是 你好 的 UTF-8 字节里那个 A0，Python 会把它单独解成 U+F8F0（一个不可见的私有区字符，夹在 菴 与 螂ｽ 之间）， 浏览器原生解码器却输出 � —— 同一串字节，两种结果。中文因为字节分布容易踩到这类边角， 日文与英文则基本碰不到。

🔌 无后端 API —— 在别的页面 / 项目里调用它
这个页面没有服务器，但依然可以被程序调用。共有四种方式，按「谁在调用」挑一种即可。 全部计算都发生在调用者的浏览器里，请求不会携带你的文字去任何第三方。

① 同源页面调用（最推荐）：直接当 JS 模块用

<script src="/alice/alice-core.js"></script>
<script>
  AliceTranslate.to("爱丽丝语");        // → "辷ｱ荳ｽ荳晁ｯｭ"（只要字符串）
  AliceTranslate.from("辷ｱ荳ｽ荳晁ｯｭ");  // → "爱丽丝语"（反向还原）

  // 需要丢失字符数等完整信息时：
  const r = AliceTranslate.toAlice("你好");
  // r = { ok:true, api:"alice-translator", version:"1.1.0",
  //       mode:"to", input:"你好", result:"菴螂ｽ", lost:0, lossless:true }
</script>

② 跨站调用：脚本标签 / JSONP 端点（不需要 CORS）

<script>
  function onAlice(d) { console.log(d.result); }   // 回调名任意
</script>
<script src="https://hxjj.dpdns.org/alice/alice-core.js?text=%E4%BD%A0%E5%A5%BD&callback=onAlice"></script>

// 支持参数：text / q / t  = 要翻译的文字
//           mode       = to（默认）| from
//           callback   = 回调函数名，支持 a.b.c 形式
//           target     = 直接把结果写进某个元素（id）的 value / textContent
// 不带任何查询串时，这个文件就是普通库，不产生任何副作用。

③ 同源 fetch / JSON：真正的 HTTP 接口

// 由 Service Worker 在浏览器内提供，路径 /alice/api
const r = await fetch("/alice/api?text=" + encodeURIComponent("世界")).then(f => f.json());
r.result;   // "荳也阜"
r.lost;     // 0

// 长文本用 POST，避免 URL 长度限制
const r2 = await fetch("/alice/api", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "很长很长的一段文字……", mode: "to" })
}).then(f => f.json());

// 不带 text 直接 GET /alice/api 会返回接口自描述（含版本与用法）

④ 页面深链：把翻译结果做成一串网址

https://hxjj.dpdns.org/alice/?text=你好&mode=to
https://hxjj.dpdns.org/alice/?t=%E4%BD%A0%E5%A5%BD&mode=from

// 打开即自动翻译并填入输入框，可直接分享 / 放进 iframe

⑤ 现场自测：真的发一次请求

点右边的按钮，会真的发一个 fetch("/alice/api?text=…") 并显示返回的 JSON。

能力边界（和真后端比）

能力本页（无后端）自建服务端
浏览器里调用✓ 模块 / JSONP / fetch✓ 需处理跨域
跨站调用✓ 脚本标签（JSONP）△ 要自己开 CORS
命令行 curl✗ 无服务器进程可访问✓
非浏览器客户端 / 机器人✗✓
要装的东西无（一张静态页）Python + 常驻进程

一句话：网页内能做的调用，无后端全都能做；网页外（curl、机器人、其它语言的程序）的调用，才必须要有后端。 因为静态站点没有任何进程能在 HTTP 层返回 text/plain 或自定义响应头 —— 本页的 /alice/api 是靠 Service Worker 在浏览器内部拦下来的， 所以它只对装过这段脚本的浏览器有效。

  "version": "1.1.0",

}
